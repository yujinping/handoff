@author yujinping

本文件是**三个客户端常驻规则块的唯一内容源**。下面 `handoff:begin` / `handoff:end`
之间的内容需**整块原样**写入下列文件末尾（三处内容必须一致）：

| 客户端 | 目标文件 | 读取机制 |
|---|---|---|
| WorkBuddy | `~/.workbuddy/MEMORY.md` | 用户级长期记忆，每次会话注入 |
| Codex | `~/.codex/AGENTS.md` | 全局 AGENTS.md（项目级 AGENTS.md 可叠加） |
| Zed | `~/.config/zed/AGENTS.md` | Personal Instructions，注入每个项目 |

改规则请改本文件，再同步三处；**客户端文件内的该块不要手改**。

**唯一允许的差异：顶层标题级别。** WorkBuddy 的 `MEMORY.md` 已有伞标题 `# 环境约定（跨项目）`，
故该块在彼处用 `##`（作为其一节）；Codex / Zed 的文件是若干并列主题的集合，故用 `#`。
其余内容三处必须逐字一致；哨兵注释行三处完全相同，便于校验与将来机械替换。

## Handoff 会话交接（常驻规则）

**生效范围**：已安装 `handoff`，且 `handoff id` 派生的 host_alias 属于本机已登记域（默认
`codeup` / `gitee` / `github`），或该 project_id 已有任务文档（`handoff list --open` 命中）。
**不满足则静默跳过**，不要提及本规则。

**规则 1 — 收尾即落盘**：任务到达可交接节点（完成一个阶段 / 用户说"交接""收尾""保存进度""先到这" /
会话即将结束）时，按 `handoff` 技能的 **save 流程**把进度写入任务文档并推送；
**不得**只在对话里总结就结束。

**规则 2 — 续做先取档**：用户说"继续""接着做""恢复""续做"某任务时，**先取档再动手**：
`handoff sync` → `handoff list --open` → `handoff show <project_id>/<slug>` → 读完文档再执行；
**禁止**凭记忆续做。（`sync` 因无 remote 或无网络失败**不阻断**，继续读本地档即可。）

**红线（不可让）**

1. 交接文档**禁止**写入 token / 密钥 / 口令 / 凭据 —— `scan` 会阻断，但应先自查。
2. **信任域**：`codeup:` 项目只进 work store，个人项目只进 personal store；跨域即信息外泄。
3. **不强制推送**：任何情况下不用 `--force` / `--force-with-lease`。

> 完整流程与冲突处置表见 `handoff` 技能 SKILL.md。

## 设计说明

**为什么只有两条规则。** 常驻规则是**每次会话都要付 token 成本**的内容，且与 SKILL.md 存在天然的
职责分工：

| 层 | 载体 | 性质 | 内容 |
|---|---|---|---|
| 触发层 | 本文件 → 三客户端常驻规则 | 常驻、必读 | **何时**该交接 / 该取档 + 红线 |
| 执行层 | `SKILL.md` | 按需加载 | **怎么做**：save / resume 完整流程、冲突处置表 |

规则只回答「何时」，不复制「怎么做」——流程细节一旦写进常驻块，就会与 SKILL.md 双向漂移。

**为什么必须有「生效范围」判据。** `handoff derive_from_dir` 在无 remote 时会**兜底**
`local:<目录基名>`，即对**任意目录**都能派生成功。若规则不设判据，「完成任务即交接」将在任何
临时目录触发并把 `local:*` 噪声写进 personal store。判据把触发面收敛到「已登记托管域」或
「已有任务文档」两类真项目上。

**为什么 `sync` 失败不阻断。** 规则 2 的目的是「以磁盘上的文档为真相源」；`sync` 只是尽量取新。
store 未配 remote（如首次部署）或离线时，`git pull` 必然非零退出——若视为错误，续做流程会被
无谓卡死。文件本地的历史版本仍优于模型记忆。

**已明确排除（按 Q4=A 收敛）。**

- 客户端 Hook（WorkBuddy SessionStart / Codex / Zed）——平台机制各异、稳定性未知，Q4 已选「仅
  常驻规则」，不引入第二套触发路径（两条触发链一旦不一致，排障成本高于收益）。
- 规则文本内联完整流程 —— 见上表职责分工。
- 自动为每个项目建文档 —— 首次建文档需用户明确要求，避免仓库被自动灌注。

**可选后续（未实施）。** 若实践中发现模型对「生效范围」判据误判，可加 `handoff managed`
子命令（exit 0 = 当前目录属于 handoff 管理范围），把散文判据换成一条确定性指令。当前按最小可用
原则不引入。
